# Job Hunter

每天按**你的简历**，从招聘平台和大厂官网里筛出一小批真正值得看的岗位，放在本地看板上。你每天只需要花几分钟看推荐、点「已投 / 稍后 / 不感兴趣」。

> **只读采集，不自动投递、不打招呼、不发消息。** 投递由你自己完成。

- **11 家大厂官网**（腾讯、字节、阿里、蚂蚁、美团、百度、华为、小米、vivo、网易、京东）走公开接口，不需要登录，零账号风险
- **智联**自动采集（接口回放）；**BOSS / 猎聘**用「浏览即采集」：你正常刷几页，浏览器里的小脚本把页面已经收到的岗位数据交给看板，不用自动化浏览器，账号零风险
- **对照简历打分**：规则先筛 → 批量初筛 → LLM 逐条对照简历，给出依据和一句话理由
- **关键词自我优化**：按每个搜索词带来的好岗位数自动增删关键词，带探索名额和防「越搜越窄」护栏
- **只推新岗位**：推荐过、处理过的不再重复出现；标签过滤（不看 / 仅看）
- 每天约几毛钱 LLM 费用（DeepSeek）；数据全部在本地 SQLite

## 快速开始

### 1. 准备环境

| 需要 | 说明 |
|---|---|
| **macOS** | 定时任务（launchd）、系统通知、Word 简历解析用到了 macOS 自带能力。Linux / Windows 上核心流程也能跑，但定时任务要自己配 cron，没有通知 |
| **Node.js 22** | 推荐用 nvm：`nvm install 22`（仓库里有 `.nvmrc`）。better-sqlite3 是原生模块，换 Node 大版本后要 `pnpm rebuild better-sqlite3` |
| **pnpm** | `npm i -g pnpm` 或 `corepack enable` |
| **Google Chrome** | 采集用本机 Chrome（Playwright `channel: chrome`），不用额外下载浏览器 |
| **DeepSeek API Key**（强烈建议） | 不填也能跑，但只有规则分，推荐质量差很多。在 [platform.deepseek.com](https://platform.deepseek.com) 申请 |
| **你的简历** | PDF / Word / Markdown / TXT 都行，后面在看板上传 |

### 2. 安装

```bash
git clone https://github.com/scarea/job-hunter.git
cd job-hunter
nvm use            # 用 .nvmrc 里的 Node 22
pnpm install
cp .env.example .env
```

### 3. 填 `.env`（最少只填这几项）

```bash
DEEPSEEK_API_KEY=sk-...          # 打分用
TARGET_SALARY_MIN=25             # 期望月薪下限（千元）
TARGET_SALARY_IDEAL=30           # 理想月薪（千元）
CITIES=深圳                       # 目标城市
DAILY_QUERIES="大模型平台,AI网关,Agent开发,推理服务"   # 3–6 个最核心的搜索词（种子词）
```

其余配置见下文「配置项」，默认值就能用。

### 4. 启动

```bash
bash scripts/install-schedule.sh   # 安装：每天 04:00 的定时任务 + 常驻看板（开机自启、崩溃重启）
```

打开 **http://localhost:5173**，然后：

1. **⚙️ 配置 → 📄 上传简历文件**。这是打分的唯一依据，最重要的一步
2. 点 **▶ 立即运行一轮**。第一轮要 20–30 分钟（浏览器平台是刻意放慢的），可以点「📜 日志」看进度
3. 跑完后看「今日推荐」

不想装定时任务、只想先试试：`pnpm web` 启动看板，另开终端 `pnpm daily` 跑一轮。

### 5. 让体验更好的几件事（一次性）

| 做什么 | 为什么 |
|---|---|
| **简历写具体**：技术栈、做过的系统、关键数字 | LLM 是逐条对照简历判断匹配的。「熟悉后端」远不如「独立写过 20+ 模型 Provider、Temporal 编排」打分准 |
| **种子词只放 3–6 个最核心的** | 其余交给关键词策略自动扩展。种子词永不淘汰，放太多会挤占探索名额 |
| **装「浏览即采集」脚本**（看板「🧩 浏览即采集」里有步骤） | BOSS 和猎聘会拦截自动化浏览器，只能在你正常浏览时收数据。装好后点「🌐 打开今天的搜索页」，每个页面往下翻几页就行，约 2 分钟 |
| **让 Mac 凌晨 4 点醒着**：`sudo pmset repeat wakeorpoweron MTWRFSU 03:55:00` | Mac 在睡眠时，定时任务会等到你开机才跑，推荐要晚半小时才出来。锁屏没关系，但要保持登录状态（采集用的是有界面的 Chrome，窗口在屏幕外） |
| **允许通知**：系统设置 → 通知 → 「脚本编辑器」 | 有新推荐、或有平台需要你处理时才会通知 |
| **先跑一两轮再加标签** | 看到不想要的岗位类型（比如 Java、外包）再加「不看」标签，比一开始拍脑袋精准 |

## 每天怎么用

1. 打开看板 http://localhost:5173
2. 看「今日推荐」，每个岗位点一下：**✓ 已投** / **⏰ 稍后** / **✕ 不感兴趣**
3. 顶部某个平台卡片变黄、显示「去处理」时，点一下 → 弹出的窗口里滑一下验证或扫码登录 → 自动检测完成并关窗

**推荐规则**：只推「当前打分版本 ≥ 68 分、没推荐过、没处理过、最近 14 天还在招」的岗位；同一公司每天最多 5 个；同公司同名岗位只推一个。推荐过但没处理的进「待处理」，不会第二天又冒出来。「不感兴趣」的以后不再出现，也不再花钱打分。

## 数据来源

| 来源 | 方式 | 账号风险 | 说明 |
|---|---|---|---|
| 腾讯官网 | 公开接口 | 无 | 深圳岗位多，含完整 JD；没有薪资 |
| 大厂官网（10 家） | 公开接口 | 无 | 见下表；都带 JD，没有薪资 |
| 智联招聘 | 接口回放 | 低 | 实测稳定 |
| 猎聘 | 浏览即采集 | 无 | 你浏览时，脚本收下页面自己拿到的岗位列表 / 详情页 JD；猎头代招岗多 |
| BOSS 直聘 | 浏览即采集 | 无 | 同上；薪资来自接口明文（列表页文字是加密字体） |

### BOSS / 猎聘：浏览即采集

这两个平台会识别并清空自动化浏览器的页面（实测打开就是 `about:blank`），绕过检测属于规避平台的机器人防护，不做。所以换成：**你在自己的浏览器里正常浏览，脚本只把页面已经收到的数据交给本机看板。**

1. **装脚本**（二选一，装在你浏览招聘网站的那个浏览器里）
   - 油猴：装 Tampermonkey → 看板「🧩 浏览即采集」点「下载油猴脚本」→ 安装（之后会从看板自动更新）
   - 插件：`chrome://extensions` → 开发者模式 →「加载已解压的扩展程序」→ 选 `extension/` 目录
2. 第一次在 BOSS / 猎聘页面上，Chrome 可能弹「允许访问本地网络上的设备」→ 点允许
3. 看板点「🌐 打开今天的搜索页」：用关键词策略当天选出的词，在 Chrome 里打开 BOSS / 猎聘 / 智联的搜索页（`SEARCH_BROWSER` 可改浏览器）
4. 每个页面往下翻几页；想看 JD 就点开岗位。新岗位导入 1 分钟后自动打分，够格的追加进「今日推荐」

脚本的边界：只旁听页面自己的 XHR / fetch 响应、只读当前打开的详情页文字；**不向招聘网站发任何请求、不点击、不滚动**。唯一的外发是 POST 到本机 `127.0.0.1:5173`。源码只有一份：`src/server/public/job-hunter.user.js`，插件的 `extension/content.js` 由 `scripts/build-extension.sh` 生成。

### 大厂官网

每家一个适配器（`src/collectors/official/`），都实测过：无需登录、无签名。单家公司改版失效只跳过这家。

| 公司 | 城市筛选 | 备注 |
|---|---|---|
| 字节跳动 / 小米 | 服务端 | 飞书招聘同一套系统，一个适配器 |
| 阿里巴巴 / 蚂蚁集团 | 服务端 | 阿里用双提交 XSRF cookie（自己生成，不是签名） |
| 美团 | 服务端 | 关键词会匹配 JD 正文，结果偏宽，靠初筛过滤 |
| 百度 / 华为 / vivo | 服务端 | |
| 网易 | 本地过滤 | |
| 京东 | 只能到省 | |

没接的：大疆（列表接口返回加密数据，解密等于绕过它的反爬保护，不做）、快手（需要签名）、OPPO（没有公开的社招接口）。

> 适配器目前按深圳写死了城市编码（`CT_128`、`440300`、`4403` 等）。换城市需要改对应适配器里的编码，`CITIES` 只影响打分和过滤。

### 采集原则

- **只自动采集公开接口和智联**：BOSS / 猎聘不做自动化采集（见上）
- **不硬闯**：识别到验证页 / 登录墙 / 风控码立即停下该平台，冷却 12 小时，期间不再请求，等你「去处理」或自然解封
- **有界面浏览器**：用真实 Chrome（窗口在屏幕外），不用无头模式（会被识别）
- **省请求**：标题就能否决的岗位（外包、销售、实习、城市不符…）不去打开详情页

## 打分

```
规则先筛（外包 / 销售 / 实习 / 城市不符…一票否决，零成本）
   ↓
批量初筛（20 个一批，只排除明显和简历方向无关的）
   ↓
LLM 对照简历完整打分（技术 30 / 薪资 25 / 双休 20 / 公司 15 / 成长 10）
   ↓
标签过滤（不看 / 仅看）→ 今日推荐
```

- LLM 先列出 JD 的核心要求，再逐条对照简历，每个维度给出 JD 原文依据；不把规则分喂给 LLM（避免锚定）
- 触红线（外包公司、明确大小周、方向完全不对口…）的总分封顶 45；没有 JD 的封顶 65（不会进推荐，补到 JD 后自动重打）
- 结论（建议投 / 可投 / 不投）只由总分决定
- LLM 调用失败不入库，下次重试；连续失败 5 次自动停（多半是 key 或余额问题）

**省成本**（实测单岗位成本从 ¥0.0036 降到 ¥0.0015）：批量初筛、重复发布的岗位复用分数、输出精简、简历放在提示最前面命中 DeepSeek 前缀缓存、处理过 / 已下线 / 14 天没出现的岗位不再打分。

打分版本号 = 规则版本 + 简历指纹。改 `src/config.ts` 的规则或权重请 bump `RULES_VERSION`；改简历会自动换版本、全部重打（约 ¥1–2）。

## 关键词策略（自动调整搜索词）

搜索 → 打分 → 复盘 → 调整关键词，形成正反馈：

1. **记账**：每个关键词每轮带来了哪些岗位；收益 = 新岗位里达到推荐门槛的个数 + 0.3 × 相关岗位个数 + 0.2 × 老岗位里的高分个数
2. **选词**：每轮跑 `QUERY_BUDGET` 个词（默认 8）。📌 钉住的必跑；约 30% 名额给新词 / 样本少的词（探索）；其余按 UCB 从高到低（利用）
3. **建议**：适合你的岗位打分时，AI 顺带给 1–3 个「能搜到更多同类岗位」的词，按分数加权累计
4. **复盘**：每轮结束 AI 看「各词收益 + 建议词 + 简历」提出增删，再过护栏

**防止越搜越窄**：种子词和钉住的词永不淘汰；活跃词至少 6 个；每轮最多新增 3 个；至少跑满 3 轮才允许淘汰；淘汰满 21 天自动重新测试；新岗位变少时进入「拓宽模式」（只加不减，要求更宽泛、相邻方向的词）。

看板「🔁 关键词策略」能看到每个词的收益、下一轮会搜哪些、AI 的调整理由，也可以手动添加、钉住、淘汰、恢复，或一键采纳建议词。

## 标签过滤

看板「🏷 标签过滤」：把关键词设成标签，选「不看」「仅看」或「仅标记」。例：标签「外包」关键词「外包,驻场,外派」设为不看。改了标签，今日推荐会自动按新标签重新挑。

## 常用命令

```bash
pnpm daily                      # 跑一轮完整流程（和 04:00 的定时任务一样）
pnpm web                        # 只启动看板
pnpm collect --platforms official,zhaopin --queries "大模型,Agent" --pages 1
pnpm collect --force            # 忽略冷却期立即重试
pnpm score --limit 300          # 只打分
pnpm login                      # 处理所有需要登录 / 验证的平台（等同看板「一键处理」）
pnpm login boss --login         # 强制登录 BOSS
pnpm report                     # 导出 TOP20 到 data/
```

同一时间只能跑一个任务（文件锁）；看板上点「去处理」时如果有任务在跑，会排队，跑完自动弹窗。

## 定时任务（macOS）

```bash
bash scripts/install-schedule.sh     # 安装 / 更新（换了 Node 版本后重新运行一次）
launchctl start com.jobhunter.daily  # 立即试跑一次
bash scripts/uninstall-schedule.sh   # 卸载
tail -f logs/daily-$(date +%Y-%m-%d).log
```

| 服务 | 作用 |
|---|---|
| `com.jobhunter.daily` | 每天 04:00：采集 → 补详情 → 打分 → 关键词复盘 → 今日推荐 → 通知 |
| `com.jobhunter.web` | 看板常驻 http://localhost:5173，崩溃自动重启 |

## 配置项（.env）

| 变量 | 默认 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | — | 不填只用规则分 |
| `TARGET_SALARY_MIN` / `TARGET_SALARY_IDEAL` | 25 / 30 | 期望月薪（千元） |
| `CITIES` / `ACCEPT_REMOTE` | 深圳 / true | 目标城市（逗号分隔）；外地岗位一票否决 |
| `MUST_HAVE` / `AVOID` | 双休 / 外包,驻场,… | 硬要求 / 不想要（给 LLM 判断红线用） |
| `DAILY_QUERIES` | 见 `.env.example` | 种子关键词（永不淘汰）；每轮实际搜哪些由关键词策略决定 |
| `TENCENT_QUERIES` / `OFFICIAL_QUERIES` | 大模型,AI,Agent,推理,后台开发,后端 | 官网用宽词，交给打分去筛 |
| `OFFICIAL_SOURCES` | 全部 | 只跑部分官网，如 `bytedance,baidu` |
| `MAX_PAGES` | 2 | 每个关键词翻几页 |
| `DETAIL_LIMIT` | 30 | 每个浏览器平台每天最多补几个详情页 |
| `SCORE_LIMIT` / `SCORE_CONCURRENCY` | 200 / 4 | 每天最多打分数 / 并发 |
| `TOP_N` / `MIN_SCORE` / `STALE_DAYS` / `MAX_PER_COMPANY` | 20 / 68 / 14 / 5 | 每天最多推荐几个 / 推荐门槛 / 多少天没出现算过期 / 同一公司每天最多几个 |
| `QUERY_BUDGET` / `BREADTH_MIN_NEW` | 8 / 30 | 每轮给招聘平台跑几个词 / 新岗位少于多少进入拓宽模式 |
| `BLOCK_COOLDOWN_HOURS` | 12 | 平台被拦后冷却多久 |
| `SEARCH_BROWSER` | Google Chrome | 「打开今天的搜索页」用哪个浏览器（要和装采集脚本的一致） |
| `OPEN_KEYWORDS_COUNT` / `OPEN_PLATFORMS` | 2 / boss,liepin,zhaopin | 打开搜索页用前几个词 / 哪些平台 |
| `PRICE_IN` / `PRICE_IN_HIT` / `PRICE_OUT` | 3 / 0.3 / 6 | 成本统计用的单价（元 / 百万 token），按官网价格调整 |

看板「⚙️ 配置」里改的是其中几项（Key、种子词、页数、推荐数），保存时不会动 `.env` 里的其他配置。

## 常见问题

**平台卡片一直是黄色「需要验证 / 需要登录」**：点「去处理」，在弹出的窗口里完成后会自动检测；检测不到就点卡片上的「我已完成」。不处理也没关系，冷却 12 小时后会自动再试。

**`ERR_DLOPEN_FAILED` / better-sqlite3 版本不匹配**：Node 大版本变了。`nvm use 22 && pnpm rebuild better-sqlite3`，再运行一次 `bash scripts/install-schedule.sh`。

**凌晨没有跑**：看 `logs/daily-*.log`。最常见是 Mac 在睡眠（见上面的 `pmset`），或者 Node 路径变了（重新运行安装脚本）。

**推荐太少**：正常现象——门槛是 68 分，宁缺毋滥。可以降低 `MIN_SCORE`，或在「关键词策略」里加词，或用「浏览即采集」刷几页 BOSS / 猎聘。

**浏览时右下角徽标显示「连不上看板」**：看板没启动（`pnpm web` 或安装脚本），或者浏览器没允许访问本地网络（地址栏左侧的站点设置里打开「本地网络访问」）。

**推荐不准**：先检查简历是否具体；再用「不看」标签排除不想要的方向；`src/config.ts` 里可以改权重和否决规则（改完 bump `RULES_VERSION`）。
